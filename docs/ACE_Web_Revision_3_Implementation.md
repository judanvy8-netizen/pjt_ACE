# ACE 3차 구현 및 확인 기록

## 기능

| 항목 | 구현 |
| --- | --- |
| 등록과 분석 | 여러 장을 데이터셋으로 먼저 저장한다. 분석 시작 시 회차와 사진·버전별 작업을 생성한다. |
| 엔진 | Python FastAPI가 main, main-1, main-2를 선택한다. 각 버전의 CLI가 같은 추론 코드를 사용한다. |
| 진행과 재시도 | Spring의 단일 작업 스레드에서 순차 실행한다. 실패한 작업만 다시 시도하거나 서버 재시작 후 대기 작업을 이어서 실행할 수 있다. |
| 비교 | 보관된 제출본 또는 웹 분석 데이터셋과 회차를 선택한다. 원본과 결과 확대, 기준 표의 모델명을 제공한다. |
| CSV 검수 | 기준 파일명과 SHA-256을 확인한다. 종류·비고는 설명으로 표시하며 사진별 마릿수 정답으로 성공 결과를 평가한다. |
| DB | dataset·analysis_round를 추가했다. 회차·사진·버전은 유일하다. 3차에는 기존 DB 이관 절차 대신 빈 ace_web 초기화 절차를 사용한다. |

## Windows 인수 확인

1. 기존 Spring Boot를 종료하고 README에 따라 DB 초기화와 빌드를 수행한다.
2. 정상 사진 2장을 등록한다. 회차가 없는 상태에서 분석을 시작해 6건을 확인한다.
3. 별도 데이터셋에 정상 JPG 2장과 확장자가 JPG인 손상 파일 1장을 등록한다. 정상 결과 6건과 실패 3건을 확인하고, 개별 재시도 시 기존 성공 결과가 유지되는지 확인한다.
4. 같은 데이터셋을 다시 실행해 이전 회차가 남아 있는지 확인한다.
5. 기준 사진과 이름만 같은 사진, 미등록 사진, img_039.jpg의 0/0 정답을 확인한다.
6. 40장 회차에 작업 120건이 표시되는지 확인한다. DB 설계 화면에서 3차 ERD와 Excel 정의서를 연다.

Gradle 배포 파일 다운로드가 실행 환경의 네트워크에서 실패했다. 전체 Spring 빌드, MySQL 8.4 연동, 실제 모델 추론을 포함한 Windows 통합 실행은 위 순서로 확인한다.

## 이번 검증에서 확인한 항목

- Java 17 문법 모드로 Java 소스를 파싱했다. Python 및 JavaScript 문법을 확인했다.
- FastAPI에 대체 모델을 연결해 세 버전의 선택, 결과 파일 분리, 같은 실행 재요청, 잘못된 버전·경로·사진 응답을 확인했다.
- DB 설계 Excel의 61개 컬럼과 외래키 9개를 3차 DDL과 대조했고 두 ERD 이미지와 시트 미리보기를 확인했다.
