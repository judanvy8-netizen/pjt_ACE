## 1. 목표와 기준

학생이 브라우저에서 사진을 올리면 ACE가 개·고양이 마릿수와 박스별 품종 후보를 보여준다. 이력에서 원본과 검출 이미지를 다시 보고, 정답을 입력하거나 수정해 오답을 분석한다.

첫 목표는 **같은 사진과 모델을 사용했을 때 기존 Python 실행과 웹서비스의 결과를 재현하는 것**이다. 제출 CSV를 다시 계산한 결과는 마릿수 **31/40장(77.5%)**, 미검출과 종 오류를 포함한 품종 **27/50마리(54.0%)**다. 11월 11일에 보고된 36/40 개선판은 해당 소스와 조건을 확보해 별도로 검증한다.

### 개발 환경

| 항목 | 적용 기준 |

| Java | JDK 17로 빌드하고 실행 |

Spring Boot 4.x 안에서 사용할 세부 버전과 Gradle Wrapper 버전은 JDK 17 환경의 빌드·실행 확인 후 기록한다. LOOK의 빌드 파일은 Spring Boot 4.1.2와 Java 17 컴파일 대상을 지정한다.

포트 후보는 Spring 8080, Python 8090, MySQL 3306이다. LOOK의 Python 기본값은 3001이며, ACE에서는 Windows 포트 예약과 다른 프로젝트의 사용 여부를 함께 확인한다. 포트 가용성을 확인한 뒤 정하고, Python은 같은 PC에서만 연결하도록 루프백으로 실행한다.

## 3. 사진 분석 흐름과 API 초안

1. Spring이 업로드 형식과 크기를 검사하고 고유 실행 ID를 발급한다. 원본은 `ACE_STORAGE/inbox/<run_id>/`에 저장한다.
2. Spring이 FastAPI의 `POST /api/infer`에 `run_id`와 `relative_path`를 보낸다. FastAPI는 공유 폴더 경로와 실제 이미지 디코딩을 확인한다.
3. FastAPI가 제출본 `main-2.py`의 전처리, 검출, 품종 후보 분류, 박스 보정 순서로 처리한다. 모델은 서버에서 재사용하며, CLI와 웹이 같은 사진 한 장 처리 로직을 호출하도록 구성한다.
4. FastAPI가 검출 이미지를 `ACE_STORAGE/results/<run_id>/`에 저장한다. 응답에는 실행 ID, 고양이·개 마릿수, 결과 상대 경로, 처리 시간, 엔진·모델 식별값과 추론 설정을 담는다. 객체 목록에는 박스 번호·좌표와 기준 이미지 크기, 검출 종류·점수, 품종 후보·점수, 분류 상태를 담는다.
5. Spring이 결과를 DB에 저장하고 브라우저에 보여준다. 정답이 있으면 종류별 마릿수 오차를 계산하고, 나중에 정답을 추가하거나 고치면 평가를 다시 계산한다.

검출 0마리는 정상 결과다. 정답 미입력은 ‘미평가’, 입력한 0/0은 평가 가능한 정답으로 처리한다. 잘못된 이미지, Python 연결 실패와 DB 저장 실패는 각각 화면에 표시한다. 저장을 재시도할 때는 동일 실행 ID로 중복 등록을 막는다. 동일 파일명 업로드와 공유 폴더 밖 경로 요청도 확인한다.

## 4. 화면과 DB 초안

| 화면 | 기능 |
| --- | --- |
| 사진 분석 | 사진 업로드, 원본과 검출 이미지, 개·고양이 마릿수, 박스 번호별 품종 후보·점수 |
| 이력 목록·상세 | 시각, 파일명, 모델, 예측/정답, 처리·평가 상태, 이미지 다시 보기 |
| 정답·오답 분석 | 정답 마릿수 입력·수정, 종류별 오차 표시, 벤치마크의 품종 비교 및 오답 조회 |

| 테이블 | 저장 내용 |
| --- | --- |

| `detected_pet` | 실행별 박스 번호, 종류·좌표, 품종 후보, 각 점수와 분류 상태 |

원본과 결과 파일은 공유 폴더에 두고 DB에는 경로를 저장한다. 정답 수정 시 새 정답 버전으로 평가를 생성해 기존 예측과 평가 이력을 보존한다. 사진별 마릿수 일치와 개체별 품종 일치에는 각각 분모를 표시한다. 현재 품종 비교는 사람이 정답 개체와 예측 박스를 연결하는 방식으로 시작한다. 미검출, 종 오류, 품종 불일치, 모델 지원 범위 밖을 구분하고, 정답 박스 좌표를 확보한 뒤 자동 매칭을 검토한다.

### 검증 체크리스트

- [ ] Windows 새 작업 폴더에서 JDK 17과 Gradle Wrapper로 Spring Boot 4.x를 빌드하고 실행한다. MySQL 8.4의 ACE 전용 DB에 연결하고 접속 비밀번호는 로컬 설정으로 주입한다.

- [ ] 종 오류 T18·T31·T39와 미검출·혼합 장면 T25·T33·T34를 사례별로 기록한다. 웹 전환 성과와 모델 개선 성과는 각 실행 결과로 확인한다.
- [ ] 정답 미입력, 정답 0/0, 정답 수정, 잘못된 파일, AI 서버 중단, DB 저장 실패, 중복 저장 재시도를 확인한다.

## 6. 구현 착수 전 확인

학생 PC에 JDK 17과 MySQL 8.4가 설치되어 있는지 확인한다. Python 가상환경 위치, 가용 포트, 공유 폴더 위치, 업로드 제한을 기록한다. 수업 PC에서 로컬 시연하는 것을 초기 전제로 잡았다. 웹캠과 동영상에서 같은 동물이 여러 프레임에 반복 등장하므로, 후속 단계에서 프레임별 마릿수 표시와 영상 전체의 고유 개체 집계 요구를 먼저 정한다.
