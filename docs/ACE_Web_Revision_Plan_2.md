# 3조 ACE 웹서비스 수정 계획서

- 작성일 2026년 11월 13일
- 상태: PDCA 계획(P) · 검토용
- 검토 기준: 현재 `ACE_Web_Project.zip`, 프로젝트 `회의록.md`, 3조 대화 기록
- 적용 환경: Spring Boot 4.x · JDK 17 · Gradle · MySQL 8.4 · Python FastAPI

## 1. 화면 구성

홈은 **프로젝트 소개와 개선 과정**을 보여주는 시작 화면으로 구성한다. 사진 업로드 폼은 하위 메뉴의 **사진 분석**으로 옮긴다.

| 메뉴 | 화면에서 할 수 있는 일 |
| --- | --- |
| 홈 `/` | ACE 소개, 팀 역할과 소개 영상, 버전 개선 요약. ‘버전 비교 보기’와 ‘사진 분석 시작’으로 이동 |
| 버전 비교 `/versions` | 세 버전의 기능과 성능을 한 화면에서 비교하고, 사진별 원본·처리 이미지·CSV 상세 조회 |
| 사진 분석 `/analyze` | 여러 사진을 한 번에 선택하고 분석. 사진별 결과와 정답 검수 화면으로 이동 |
| 분석 이력 `/history` | 기존 결과 조회, 정답 수정 이력 확인, 오답 보기 |
| DB 설계 `/db-design` | 기존 개념 ER, 물리 ERD, Excel 테이블 정의서 조회 |

기존 **제출본 검증표**는 버전 비교 화면에서 ‘오답·품종 검증’으로 연결한다. 상세 URL은 구현 시 기존 링크와의 호환을 확인한다.

## 2. 홈 화면 개선

| 항목 | 확정 내용 |
| --- | --- |
| 팀명 | ACE |
| ACE의 의미 | AI CREATE EVERYTHING |
| 슬로건 | ALWAYS CHALLENGE TOGETHER |
| 프로젝트 주제 | 반려동물 사진에서 개·고양이 분류 및 품종 분류 |
| 소개 영상 | `ACE 인트로 영상v2.mp4` · 약 10초 · 1280×720 · H.264/AAC |

첫 화면에 팀명, ACE의 의미, 슬로건과 프로젝트 주제를 배치한다. 첨부 영상을 재생 버튼으로 볼 수 있게 하고, 대표 시연 사진과 ‘버전 비교 보기’, ‘사진 분석 시작’으로 이동하는 링크를 제공한다. 별도 로고를 사용하려면 제공된 로고 파일을 적용하고, 기본 제목에는 팀명 ACE를 사용한다.

### 팀원 소개

| 이름 | 역할 |
| --- | --- |
| 김시우 | 조장 |
| 구자성 | 입력 데이터 담당 |
| 이대건 | AI 검출 실행 담당 |
| 양영석 | AI 검출 실행 담당 |
| 이승규 | 시각화 및 결과 저장 |
| 이연호 | 검증 및 오류 분석 담당 |
| 배준우 | 문서·시연·발표 담당 |

홈 하단에는 `main → main-1 → main-2`의 기능 변화와 사진별 마릿수 일치 건수를 요약한다. 세부 표와 오류 분석은 ‘버전 비교 보기’에서 연다.

## 3. 세 버전 결과 비교

### 현재 ZIP에서 확인한 자료

| 버전 | 주요 변화 | 결과 이미지 | 집계 CSV | 분류 CSV | 사진별 마릿수 일치 |
| --- | --- | ---: | --- | --- | ---: |
| `main` | YOLO로 개·고양이 검출 및 집계 | 40장 | `pet_counts.csv` | 분류 기능 없음 | 28/40장 |
| `main-1` | 검출 영역을 잘라 ImageNet 품종 후보 분류 | 40장 | `pet_counts.csv` | `pet_classifications.csv` | 28/40장 |
| `main-2` | 고양이 전용 품종 분류, 중복 박스 제거, 넓은 고양이 박스 재검출, 한글 표시 | 40장 | `pet_counts.csv` | `pet_classifications.csv` | 31/40장 |

수치는 제출본 `outputs/<버전>/pet_counts.csv`를 `data/ground_truth.csv`와 파일명으로 맞추어 재계산했다. 고양이 수와 개 수가 모두 맞은 사진을 한 건으로 센다.

### 화면과 데이터 연결

- **비교 요약**에서 세 버전의 기능 변화, 마릿수 일치 건수, 이전 버전에서 새로 맞거나 틀린 사진 수를 표시한다.
- **사진별 상세**에서 원본 1장, 버전별 결과 이미지, 개·고양이 정답과 예측을 나란히 보여준다. 화면이 좁으면 버전 탭을 사용한다.
- **오답·품종 검증**에서는 프로젝트 루트의 `test_cases.csv` 40행과 `test_cases_classification.csv` 54행을 표시한다. 검증표는 제출 시점의 `main-2` 자료로 표시하고, 다른 버전의 품종 점수는 별도 채점 근거가 있을 때 계산한다. 박스 번호는 각 버전의 이미지 안에서만 해석한다.
- 대표 비교 사례로 T23·T28·T29를 제시한다. 제출 기록에서 `main-1` 대비 `main-2`의 마릿수가 이 세 사진에서 정답과 일치했다. `main → main-1`에서는 T06·T15가 개선되고 T23·T28이 새로 틀려 전체 점수는 같았다.
- 비교는 **보관된 결과**를 읽어서 보여준다. 화면을 열 때 모델을 다시 실행하지 않는다. 사진 분석 메뉴의 신규 분석에는 제출본 기반 `main-2` 엔진을 사용한다는 구현안을 전제로 잡았다.
- 지정한 버전 폴더와 파일만 읽는다. CSV는 BOM과 따옴표가 포함된 필드를 처리하며, 누락·중복 행은 ‘자료 없음’ 또는 ‘확인 필요’로 표시한다. 버전별 일치율은 같은 입력 집합으로 계산하고 누락 건수를 표시한다. 실시간 웹 분석 결과는 기존 `outputs` 비교 자료를 덮어쓰지 않는다.

## 4. 복수 사진 분석

1. 사진 분석 메뉴에서 여러 파일을 선택한다. 파일명과 개수를 확인한 뒤 ‘분석 시작’을 한 번 누른다.
2. Spring이 사진별 형식과 크기를 확인하고 개별 실행 ID를 발급한다. 동일 파일명의 사진도 각 실행 ID로 저장한다. 최초 구현은 CPU 환경에 맞춰 순서대로 분석하고 진행 수와 사진별 상태를 표시한다.
3. 한 사진이 실패해도 나머지를 처리한다. 결과 목록에서 성공·실패·정답 검수 대기 상태를 구분한다. 실패한 사진만 해당 실행 ID로 재시도한다.
4. 각 사진의 상세 화면에서 원본, 검출 이미지, 마릿수, 박스별 품종 후보, 정답 검수 폼을 본다. 선택 가능한 파일 수와 업로드 용량은 학생 PC에서 확인 후 확정한다.

## 5. CSV 정답을 먼저 보여주고 사람이 검수

| 상황 | 상세 화면의 동작 |
| --- | --- |
| 제공된 기준 사진과 일치 | `data/ground_truth.csv`에서 종류별 마릿수와 품종·위치 설명을 불러와 ‘CSV 정답 · 검수 대기’로 표시 |
| 파일명은 같고 내용이 다름 | 자동으로 정답을 채우지 않고 사용자가 확인해 입력 |
| 등록되지 않은 사진 | 빈 정답 폼과 ‘등록된 정답 없음’ 표시 |
| 정답이 0/0 | 두 칸을 모두 0으로 표시하고 일반 정답과 동일하게 검수 |
| 이미 검수한 기록을 다시 엶 | 가장 최근에 저장된 정답을 표시하고 이전 버전은 이력에서 조회 |

- **매칭 기준**은 업로드한 파일명과 기준 이미지의 파일 내용이다. `data/images` 원본과 SHA-256을 대조한다. 파일명만 같아서 다른 사진에 정답이 붙는 경우를 막는다.
- CSV의 마릿수는 수정 가능한 초안으로 표시한다. `종류` 컬럼의 품종·위치 설명도 함께 보여준다. 사진에 여러 동물이 있거나 설명이 모호할 때는 사람이 결과 박스를 확인해 개체를 연결한다.
- 사용자는 원본과 결과 이미지를 보고 마릿수·품종·박스 대응을 확인하거나 수정한 뒤 **검수 완료·정답 저장**을 누른다. 이 시점에 MySQL에 정답 버전과 평가를 저장한다. CSV 원본은 유지한다.
- 오류 분석은 검수한 정답을 기준으로 한다. 마릿수 불일치, 미검출, 종류 오류, 품종 불일치, 모델 지원 범위 밖을 구분한다.

## 6. 작업 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 홈과 메뉴 구조 개편 | 홈에서 ACE 소개와 버전 요약을 보고 비교·분석 화면으로 이동한다. 첨부 인트로 영상의 재생과 팀원 7명의 이름·역할 표시를 확인한다. |
| 2 | 버전 비교 화면 | 같은 기준 사진 40장으로 28/40·28/40·31/40을 재현한다. 원본·세 결과 이미지·CSV 상세와 T29 오류 차이를 화면에서 확인한다. |
| 3 | 복수 사진 분석 | 정상 사진 2장과 오류 사진 1장을 함께 선택한다. 정상 2건은 결과가 남고 오류 1건은 개별 재시도가 가능하다. |
| 4 | CSV 정답 검수 | 기준 사진, 동명 다른 사진, 미등록 사진, 정답 0/0을 확인한다. 검수 저장과 수정 후 정답 버전·평가 이력이 남는다. |
| 5 | 통합 점검 및 문서 | Windows·JDK 17·MySQL 8.4에서 화면과 재시작 후 이력을 확인하고 README와 개발기록을 업데이트한다. |

기존 Spring MVC 구조에서 홈·버전 비교는 조회 기능으로 추가하고, 복수 분석과 정답 검수는 기존 `analysis`, `media`, `truth` 도메인에 연결한다. 기존 단일 분석 이력과 DB 설계 자료의 조회를 확인한다. 이번 산출물은 수정 계획서이며 구현은 계획 검토 후 진행한다.
