# ACE 사진 비교와 검수 개선

## 적용 범위

| 화면 | 변경 |
| --- | --- |
| 사진 분석 `/analyze` | 오른쪽 안내 카드에 파일 선택, 데이터셋 등록, 분석 시작, 결과 검수, 새 회차 실행 절차를 표시합니다. 화면이 좁으면 등록 화면 아래에 표시합니다. |
| 분석 이력 `/history` | 같은 회차와 입력 사진의 모델 행은 동일한 비교 URL로 연결됩니다. 평가 결과와 검수 상태를 각각 표시합니다. 예전 회차 없는 실행은 모델 분석 상세로 연결됩니다. |
| 회차별 사진 `/rounds/{id}/photos/{inputId}` | 원본과 세 결과, 정답 정보, 마릿수 오차, 버전별 품종 후보 표를 표시합니다. 검수 저장이 끝나면 같은 비교 화면으로 돌아갑니다. |
| 기준 사진 `/versions/photos/{filename}` | 기준 사진 01~40 선택, 이전·다음과 마우스 확대 표시를 같은 방식으로 사용합니다. |

## 사진 탐색과 표시

- 기준 사진은 파일명 순서이며 회차 사진은 같은 회차의 파일명과 입력 ID 순으로 정렬합니다. 같은 파일명이라도 해당 입력 ID로 열립니다.
- 첫 사진의 이전 링크와 마지막 사진의 다음 링크는 비활성화됩니다. 한 장만 등록한 회차에서는 두 링크가 비활성화됩니다.
- 사진을 누르면 원본 또는 해당 모델의 이미지를 확대합니다. 닫기 버튼이나 Esc를 누르면 원래 선택한 이미지로 키보드 포커스가 돌아옵니다.
- 화면에서 CSV의 종류 설명과 비고를 표시합니다. 모델의 품종 표는 저장된 검출 박스 기준입니다. 품종 일치 요약은 별도 판정이며 순서 무관 종별 품종 비교를 적용합니다.

## 검수 저장 흐름

1. Spring MVC의 `DatasetController`에서 요청한 회차에 사진이 있는지 확인합니다.
2. `ReferenceTruthService`가 파일명과 SHA-256이 일치하는 기준 사진의 CSV 정답을 찾습니다. `DatasetService`는 저장 전에도 같은 판정식으로 비교 결과를 표시합니다.
3. **검수 저장**을 누르면 `ReviewService`가 해당 회차의 성공 결과를 기준으로 입력 사진을 잠급니다. 입력 사진 마릿수와 개체 정답을 저장하고 성공 결과를 평가합니다. 같은 정답이 이미 저장된 경우 정답 버전을 추가하지 않습니다.
4. 분석 이력은 입력 사진 ID에 저장된 정답을 기준으로 **검수완료**를 표시합니다. 해당 입력의 다른 회차 또는 나중에 성공한 모델도 정답을 공유합니다.

DB 테이블과 Flyway 스크립트는 4차 개선판과 같습니다. 기존 4차 DB와 같은 사진 저장 위치로 실행하면 기존 기록을 조회할 수 있습니다.

## 실행 확인

- [README의 준비 및 실행 방법](../README.md)을 따라 새 JAR를 빌드한 뒤 확인합니다.
- 기준 사진 29번을 열면 고양이 2마리와 왼쪽 페르시안, 오른쪽 스코티시 폴드가 표시됩니다.
- 같은 회차와 같은 사진의 세 모델 행이 동일 URL로 이동하는지 확인하고 검수 저장 전후 상태를 비교합니다.
- 사진 선택과 이전·다음 이동 시 원본, 결과 카드, 품종 표와 검수 상태가 해당 사진 기준으로 바뀌는지 확인합니다.
- 회차 내에서 처리 대기, 실패, 성공 상태가 함께 있는 경우 화면을 열어 성공한 결과만 보여주고 나머지는 해당 상태를 표시하는지 확인합니다.
- 정답표에 없는 사진과 같은 이름이지만 다른 내용으로 업로드한 사진은 CSV 정답을 연결하지 않는지 확인합니다.
