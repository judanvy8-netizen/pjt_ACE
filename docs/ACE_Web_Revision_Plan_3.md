- 작성일 2026년 11월 13일
- 상태: PDCA 계획(P) · 검토용

- 적용 환경: Spring Boot 4.x · JDK 17 · Gradle · MySQL 8.4 · Python FastAPI

## 1. 화면 구성

홈은 **프로젝트 소개와 개선 과정**을 보여주는 시작 화면으로 구성한다. 사진 업로드 폼은 하위 메뉴의 **사진 분석**으로 옮긴다.

| 메뉴 | 화면에서 할 수 있는 일 |
| --- | --- |
| 홈 `/` | ACE 소개, 팀 역할과 소개 영상, 버전 개선 요약. ‘버전 비교 보기’와 ‘사진 분석 시작’으로 이동 |
| 버전 비교 `/versions` | 기준 사진 결과와 웹에서 실행한 데이터셋 결과를 선택하고, 사진별 원본·세 버전 결과 조회 |
| 사진 분석 `/analyze` | 사진 여러 장을 데이터셋으로 등록한 뒤 분석 시작. 사진별·버전별 진행 상태와 결과를 조회 |
| 분석 이력 `/history` | 기존 결과 조회, 정답 수정 이력 확인, 오답 보기 |
| DB 설계 `/db-design` | 기존 개념 ER, 물리 ERD, Excel 테이블 정의서 조회 |

기존 **제출본 검증표**는 버전 비교 화면에서 ‘오답·품종 검증’으로 연결한다. 상세 URL은 구현 시 기존 링크와의 호환을 확인한다.

## 3. 세 버전 결과 비교

### 현재 ZIP에서 확인한 자료

| 버전 | 주요 변화 | 결과 이미지 | 집계 CSV | 분류 CSV | 사진별 마릿수 일치 |
| --- | --- | ---: | --- | --- | ---: |
| `main` | YOLO로 개·고양이 검출 및 집계 | 40장 | `pet_counts.csv` | 분류 기능 없음 | 28/40장 |
| `main-1` | 검출 영역을 잘라 ImageNet 품종 후보 분류 | 40장 | `pet_counts.csv` | `pet_classifications.csv` | 28/40장 |
| `main-2` | 고양이 전용 품종 분류, 중복 박스 제거, 넓은 고양이 박스 재검출, 한글 표시 | 40장 | `pet_counts.csv` | `pet_classifications.csv` | 31/40장 |

수치는 제출본 `outputs/<버전>/pet_counts.csv`를 `data/ground_truth.csv`와 파일명으로 맞추어 재계산했다. 고양이 수와 개 수가 모두 맞은 사진을 한 건으로 센다.

### 화면과 데이터 연결

- **비교 요약**에서 세 버전의 기능 변화, 마릿수 일치 건수, 이전 버전에서 새로 맞거나 틀린 사진 수를 표시한다.
- **사진별 상세**에서 원본 1장, 버전별 결과 이미지, 개·고양이 정답과 예측을 나란히 보여준다. 화면이 좁으면 버전 탭을 사용한다.
- **오답·품종 검증**에서는 프로젝트 루트의 `test_cases.csv` 40행과 `test_cases_classification.csv` 54행을 표시한다. 검증표는 제출 시점의 `main-2` 자료로 표시하고, 다른 버전의 품종 점수는 별도 채점 근거가 있을 때 계산한다. 박스 번호는 각 버전의 이미지 안에서만 해석한다.
- 대표 비교 사례로 T23·T28·T29를 제시한다. 제출 기록에서 `main-1` 대비 `main-2`의 마릿수가 이 세 사진에서 정답과 일치했다. `main → main-1`에서는 T06·T15가 개선되고 T23·T28이 새로 틀려 전체 점수는 같았다.
- 비교 화면에서 **기준 사진 40장** 또는 **웹에서 등록한 데이터셋과 분석 회차**를 선택한다. 기준 자료는 기존 `outputs`에서, 웹 분석 자료는 선택한 회차의 저장 결과에서 읽는다. 모델 실행은 사진 분석 메뉴의 **분석 시작**으로 요청한다.
- 지정한 버전 폴더와 파일만 읽는다. CSV는 BOM과 따옴표가 포함된 필드를 처리하며, 누락·중복 행은 ‘자료 없음’ 또는 ‘확인 필요’로 표시한다. 버전별 일치율은 같은 입력 집합으로 계산하고 누락 건수를 표시한다. 실시간 웹 분석 결과는 기존 `outputs` 비교 자료를 덮어쓰지 않는다.

### 추가 수정 요청 · 버전별 사용 모델 표시

- 상태: 구현 대기
- 버전 비교 화면의 요약표에 **사용 모델** 열을 추가한다. 각 모델의 파일명과 역할을 함께 표시한다.

| 버전 | 개·고양이 검출 | 품종 후보 분류 |
| --- | --- | --- |
| `main` | `yolo11n.pt` | 해당 없음 |
| `main-1` | `yolo11n.pt` | `yolo11n-cls.pt` (개·고양이, ImageNet) |
| `main-2` | `yolo11n.pt` | 개 `yolo11n-cls.pt` · 고양이 `cat_oxford_mobilenetv3.pt` |

표시 기준은 각 버전의 소스에서 지정한 모델이다. 기존 결과 CSV에는 모델 파일명 기록이 없으므로, 보관된 결과를 생성한 모델을 CSV에서 확인한 값으로 표기하지 않는다. 완료 기준은 세 버전 모두에서 검출 모델과 품종 후보 분류 모델의 역할을 확인할 수 있는 것이다.

### 추가 수정 요청 · 사진별 비교 이미지 확대

- 상태: 구현 대기
- 사진별 비교 화면(`/versions/photos/{filename}`)에서 **원본, main, main-1, main-2** 이미지 중 하나를 클릭하거나 키보드로 선택하면 같은 페이지에서 확대해 볼 수 있다.
- 확대 창에는 사진 파일명과 선택한 버전을 표시한다. 이미지는 비율을 유지하며 화면 크기에 맞춰 표시한다. **닫기** 버튼이나 `Esc` 키로 닫으면 기존 비교 위치로 돌아간다.
- 완료 기준: 예시 `img_004.jpg`의 네 이미지를 각각 열어 올바른 이미지와 버전명이 표시되는지 확인한다. 닫은 뒤 다른 버전을 선택할 수 있어야 하며, 이미지가 없는 카드에는 확대 동작을 표시하지 않는다.

## 4. 데이터셋 등록과 세 버전 분석

- 상태: 구현 대기
- 적용 대상: 사진 분석 메뉴에서 새로 등록하는 사진

| 단계 | 사용자 동작 | 시스템 처리 |
| --- | --- | --- |
| 1. 파일 선택 | 사진을 여러 장 선택하고 목록을 확인한다. | 파일명과 개수를 보여준다. |
| 2. 데이터셋 등록 | **데이터셋 등록**을 누른다. | Spring Boot가 파일을 검사하고 원본을 한 번 저장한다. 데이터셋 ID와 사진별 ID를 부여하고 등록 결과를 표시한다. |
| 3. 분석 시작 | 등록된 데이터셋에서 **분석 시작**을 누른다. | Spring Boot가 분석 회차를 생성하고, Python 서버가 같은 입력으로 `main.py`, `main-1.py`, `main-2.py`에 해당하는 로직을 각각 실행한다. 사진 40장이면 총 120개의 사진·버전 결과가 생성된다. |
| 4. 비교 | 사진 분석 결과 또는 **버전 비교**에서 데이터셋과 회차를 선택한다. | 원본과 세 결과 이미지, 개·고양이 마릿수, 해당 버전의 품종 후보, 처리 시간과 상태를 표시한다. |

### Python 실행과 결과 보존

- 기존 CLI와 웹이 버전별 Python 로직을 공유하도록 구성한다. FastAPI에는 등록한 사진의 상대 경로, 실행 ID, 허용된 버전 식별자만 전달한다. 학생 PC의 CPU를 고려해 초기에는 순차 처리하고, 브라우저가 진행 상태를 조회한다.
- 원본은 데이터셋과 사진 ID별로 보관하고, 결과는 회차·사진 ID·버전별로 저장한다. 같은 이름의 사진이 여럿 있어도 구분한다. 재분석은 새 회차를 만들며 기존 웹 결과와 제출본 `outputs/main*`을 보존한다.
- 실패한 사진·버전 조합만 같은 실행 ID로 재시도한다. 이미 성공한 결과를 보존하며, 한 버전이 실패해도 나머지 사진과 버전은 계속 처리한다. 시작 버튼을 중복 클릭해도 같은 요청이 중복 등록되지 않도록 한다.
- 버전별 정답 일치율은 같은 정답 보유 사진 집합을 기준으로 표시하고, 미평가·실패·대기 건수를 함께 표시한다. 품종 후보는 품종 분류가 있는 버전에서 표시한다.

### DB 변경 계획

현재 `analysis_run.input_id`에 유일 제약이 있어 사진 하나에 분석 결과 한 건을 연결한다. 전환 시 데이터셋과 분석 회차를 관리할 구조를 추가하고, 사진 하나에 회차별 세 분석 결과를 연결하도록 관계를 1:N으로 변경한다. 회차·사진·버전 조합에 유일 제약을 적용한다. 정답은 사진에 연결하고, 각 버전의 평가는 해당 실행 ID와 정답 버전에 연결한다.

기존 DB를 초기화하고 새 `ace_web`에 3차 `schema.sql`을 적용한다. 기존 이력 이관은 생략한다. 3차 스키마를 DB 설계 화면·물리 ERD·Excel 정의서에 반영한다.

## 5. CSV 정답 검수 간소화

- 상태: 수정 구현 대기
- 새 검수에는 `data/ground_truth.csv`에 등록된 정답만 사용한다. 파일명과 `data/images` 기준 이미지의 SHA-256이 모두 일치할 때 해당 행을 표시한다.
- 일치한 사진은 **고양이 정답·개 정답**을 읽기 전용으로 표시한다. CSV의 `종류`와 `비고`도 읽기 전용 설명으로 표시한다.
- **개체별 정답(선택)** 입력란과 구분자·박스 번호 입력 안내를 제거한다. 개체에 관한 설명은 CSV의 종류·비고로 확인한다. 예측의 박스별 검출 결과와 제출본 품종 검증표는 기존처럼 조회한다.
- 사용자는 원본, 예측, CSV 정답을 확인한 뒤 **검수 완료·정답 저장**을 누른다. 저장 시 서버에서 기준 정답을 다시 확인하고 기존 정답·평가 구조에 사진에 정답을 기록하고, 동일한 정답 버전으로 성공한 세 분석의 개·고양이 마릿수 오차와 일치 여부를 각각 기록한다.
- 동명 다른 사진이나 미등록 사진에는 **등록된 정답 없음**을 표시하고 미평가로 둔다. 기존에 저장한 평가 이력은 조회할 수 있다.

| 확인 사례 | 완료 기준 |
| --- | --- |
| `img_039.jpg` | CSV 정답은 고양이 0마리·개 0마리, 종류는 ‘해당 없음’, 비고는 ‘개와 고양이 외의 다른 동물(토끼)’로 표시한다. 개 1마리로 예측했다면 개 마릿수 오차 1로 저장한다. |
| 기준 사진과 일치 | 개체별 입력 없이 CSV 정답을 확인하고 저장할 수 있다. |
| 동명 다른 사진 또는 미등록 사진 | CSV 정답이 표시되지 않고 미평가 상태를 유지한다. |

## 6. 작업 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 홈과 메뉴 구조 개편 | 홈에서 ACE 소개와 버전 요약을 보고 비교·분석 화면으로 이동한다. 첨부 인트로 영상의 재생과 팀원 7명의 이름·역할 표시를 확인한다. |
| 2 | 버전 비교 화면 | 같은 기준 사진 40장으로 28/40·28/40·31/40을 재현한다. 원본·세 결과 이미지·CSV 상세와 T29 오류 차이를 화면에서 확인한다. |
| 3 | 데이터셋 등록과 세 버전 분석 | 등록만으로는 추론이 실행되지 않는다. 정상 사진 2장을 분석하면 6개 결과가 나오고, 40장은 120개 결과가 나온다. 사진·버전별 실패와 재시도, 다른 버전의 계속 처리를 확인한다. |
| 4 | CSV 정답 검수 | 기준 사진, 동명 다른 사진, 미등록 사진, 정답 0/0을 확인한다. 개체별 입력 없이 CSV 마릿수로 검수·저장하고 기존 평가 이력을 조회한다. |
| 5 | 통합 점검 및 문서 | Windows·JDK 17·MySQL 8.4에서 빈 DB 초기화, 새 분석 회차, 재시작 후 이력을 확인하고 README·개발기록·DB 설계 자료를 갱신한다. |

기존 Spring MVC 구조에서 홈·버전 비교는 조회 기능으로 추가하고, 복수 분석과 정답 검수는 기존 `analysis`, `media`, `truth` 도메인에 연결한다. 기존 단일 분석 이력과 DB 설계 자료의 조회를 확인한다. 이번 산출물은 수정 계획서이며 구현은 계획 검토 후 진행한다.
